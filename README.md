# CSE AWS Terraform Skeleton

This repo is the AWS Terraform skeleton aligned to the Azure full deployment IaC in: 
- [IaC_full_deployment-latest-vm-image-Azure/IaC_full_deployment-latest-vm-image/main.tf](https://github.com/csdso-wavestone/IaC_full_deployment/tree/latest-vm-image)

It deploys the same high-level components:
- Public app VM (EC2) with SSH/HTTP/HTTPS open.
- Two storage buckets (logo public-read baseline, logs private).
- Publicly reachable MySQL database baseline (RDS).
- VPC/public subnet routing and security groups.

## Files
- `versions.tf`: Terraform + provider versions.
- `variables.tf`: input variables.
- `locals.tf`: naming, tags, data sources.
- `main.tf`: resource skeleton.
- `outputs.tf`: useful deployment outputs.
- `terraform.tfvars.example`: sample variable values.

## Naming and Tagging
- Required tag baseline: `Project=cse-aws`.
- Naming convention:
  - Base prefix: `cse-sbx-<trainee>-ew3`
  - Pattern: `<prefix>-<service>-<purpose>-<nn>`
  - S3 uniqueness: `...-<accountid>`

## Usage
1. Copy example vars:
```bash
cp terraform.tfvars.example terraform.tfvars
```
2. Update sensitive and environment-specific values in `terraform.tfvars` (including `aws_profile = "cse"` unless you intentionally override it). `ec2_key_pair_name` can stay empty to auto-generate and create the key pair.
3. Run:
```bash
terraform init
terraform plan
terraform apply
```

By default this stack uses AWS CLI profile `cse` via provider variable `aws_profile`.

## NB
- This skeleton intentionally contains insecure baseline
- SSH private key is generated by Terraform and stored in state/output (ec2_private_key_pem)
